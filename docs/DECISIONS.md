# 开发依据

来源：用户引用的 ChatGPT 对话「开发物品陪伴App」（6aafd510-cac8-83eb-96c0-91647026c174），已追溯至最初的产品场景并按最新修订取舍；本聊天确认的第一版首页与沙发详情静态稿优先作为视觉基准。

1. MVP 记录个人真实拥有。未来社区和二手交易不进入第一版。
2. 首页／物品／我的，悬浮加号只在首页，提供添加物品和记录故事。
3. 物品卡仅照片、名称、陪伴天数。首页按确认视觉稿用双列网格，覆盖旧讨论中的横向卡片布局。
4. 详情沿用确认稿的照片、信息、故事／维修／评价页签与操作；补回原对话中的「来到身边的理由」，独立保留。
5. 创建时名称、分类、拥有开始日期必填；照片选填。价格后紧接购入渠道。第一次建档不强求品牌、型号、尺寸。
6. 故事不设置标题，文字或照片至少一项。视觉稿中的标题以正文首句表现。纯图故事允许保存。
7. 维修始终保留，必填日期和问题。处理方式为自由文本，不设固定枚举。摘要用「共计 2次」而不是加冒号。
8. 评价不用星级，保留「＋ 自定义」与「如果重新选择一次，你还会买它吗？」。
9. 离开不删除，保留故事、维修、评价；删除用于误建，单独二次确认。
10. 默认十类与原对话一致；一级为生活领域，二级为物品类型，上限只绑定二级。
11. 为可执行实现确定的细节：首日计1天，离开当天计入；日均 = 购入价格/陪伴天数；金额空值不同于0；记录不能在拥有区间之外。
12. 使用原生微信小程序，替换之前聊天中尚未定案的 Next.js Web App 建议。无需框架依赖。用户未提供 AppID，保留本地游客配置。
