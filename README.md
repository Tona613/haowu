# 好物｜好物相伴，日久有情

围绕真实拥有和长期陪伴的个人物品档案产品。记录一件物品来到身边后的故事、维修、评价与离开，并探索基于物品档案的真实使用分享。

这是一个持续迭代的个人产品作品，使用 AI 辅助完成需求讨论、界面探索、代码实现与测试。

## 体验与运行

在线演示（启用 GitHub Pages 后）：https://Tona613.github.io/haowu/

本地需要 Node.js 20 或更新版本：

```bash
git clone https://github.com/Tona613/haowu.git
cd haowu
npm run preview
```

打开 http://127.0.0.1:4173/ 。也可以使用微信开发者工具导入根目录；当前为开发用配置，正式发布需要自己的小程序 AppID。

## 产品问题与设计

购买后的使用经验容易散落在订单、相册和聊天中。好物以“物品档案”为核心对象，将一次购买后的长期经历串联起来。

- **目标用户**：希望整理个人物品、保留物品记忆和积累使用经验的人。
- **核心路径**：添加物品 → 记录故事／维修 → 写评价 → 标记离开后保留档案。
- **分享路径**：选择已有物品 → 编辑分享 → 预览 → 发布到本机社区。
- **设计取舍**：以持续维护档案验证需求；社区当前验证分享流程，暂不做二手交易和支付。
- **真实性探索**：区分系统建档日期与用户填写的拥有开始日期。当前是本地原型，设备时间和本地数据不能作为服务端可信证明。

## 当前能力

物品分类和搜索、最多六件的个人展台、照片、故事、维修、可修改评价、物品离开事件、建议反馈弹窗，以及社区帖子展示与本地分享流程。

## 实现与验证

微信小程序 WXML / WXSS / JavaScript；统一业务数据层；浏览器适配器复用页面源码，无需后端即可体验。

```bash
npm test
npm run check
node scripts/build-pages.cjs
```

测试覆盖生命周期、日期、金额、分类、存储失败、分享草稿和发布快照等规则。产品决策和验收记录见 [docs](docs/)。

## 当前边界

- 数据保存在访问者自己的浏览器或小程序本机；清除站点数据可能丢失记录。
- 没有账号、跨设备同步、真实多用户社区或服务器存储；“发布”仅进入本机社区。
- 收藏、回复和部分分享图标目前为界面展示，尚未形成完整互动能力。
- AI 用于研发辅助，当前没有面向用户上线的 AI 推荐或识别功能。
- 公开演示不包含作者浏览器中填写的私人档案或照片。
